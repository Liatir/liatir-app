# .lia Bundle Format

A `.lia` file is a ZIP archive with a small fixed structure. Liatir validates
the bundle signature before reading the manifest or executing any runtime
payload.

## Runtime variants

There are two supported runtimes:

| Runtime | Payload | Schema source |
| --- | --- | --- |
| `node` | `index.js` | `definePlugin({ inputs, outputs })` in source code |
| `wasm` | `plugin.wasm` | `.lia-manifest.json` in the WASM project |

Node plugins should not maintain a hand-written `.lia-manifest.json`. `lia build`
generates the manifest from the exported `definePlugin(...).main(...)` contract.

WASM tools do use `.lia-manifest.json`, because Rust/WASM cannot export the
JavaScript SDK schema at build time.

## Node bundle contents

```txt
my-plugin.lia
  _sig
  manifest.json
  index.js
```

| File | Required | Description |
| --- | --- | --- |
| `_sig` | Yes | Text file containing exactly `LIATIR/1`. |
| `manifest.json` | Yes | Generated metadata, runtime, input schema, and output schema. |
| `index.js` | Yes | ESM bundle generated from the Node plugin entry point. |

## WASM bundle contents

```txt
my-tool.lia
  _sig
  manifest.json
  plugin.wasm
```

| File | Required | Description |
| --- | --- | --- |
| `_sig` | Yes | Text file containing exactly `LIATIR/1`. |
| `manifest.json` | Yes | Metadata, runtime, input schema, and output schema. |
| `plugin.wasm` | Yes | Rust/WASI artifact compiled by `cargo build --target wasm32-wasip1`. |

## Generated Node manifest

For Node plugins, this manifest is generated by `lia build` after bundling and
validating the default export.

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "What this plugin does",
  "runtime": "node",
  "category": "Utilities",
  "tags": ["text"],
  "inputSchema": {
    "text": {
      "type": "string",
      "label": "Text",
      "description": "Text to analyze.",
      "required": true,
      "default": "hello from Liatir"
    }
  },
  "outputSchema": {
    "length": {
      "type": "number",
      "label": "Length",
      "description": "Number of characters in the input text.",
      "format": "integer"
    }
  }
}
```

## Node entry point

The Node entry point must default-export the result of
`definePlugin({ inputs, outputs }).main(...)`.

```ts
import { definePlugin, field, type PluginContext } from "@liatir/sdk";

const liatirPlugin = definePlugin({
  inputs: {
    text: field.string({
      label: "Text",
      description: "Text to analyze.",
      required: true,
      default: "hello from Liatir",
    }),
  },
  outputs: {
    length: field.number({
      label: "Length",
      description: "Number of characters in the input text.",
      format: "integer",
    }),
  },
});

export default liatirPlugin.main(async ({ input, lia }: PluginContext<typeof liatirPlugin>) => {
  return {
    length: input.text.length,
  };
});
```

`lia build` rejects Node plugins that export the unfinished contract without
`.main(...)`, or that do not expose the SDK-controlled runtime shape.

## Field schemas

Input fields may use:

- `string`
- `number`
- `boolean`
- `file`

Output fields may use:

- `string`
- `number`
- `boolean`
- `file`
- `stats`
- `json`

Shared field properties include:

| Property | Description |
| --- | --- |
| `label` | Human-readable label shown in the UI. |
| `description` | Short explanation shown near the field. |
| `required` | Whether the field must be filled before running. |
| `default` | Default value applied by the UI and by `lia dev`. |
| `accept` | Accepted file extensions for file inputs. |
| `ext` | Expected file extensions for file outputs. |
| `format` | Numeric output display hint: `integer`, `decimal`, `percent`, or `bytes`. |

## File outputs

If an output field has `type: "file"`, the returned value can reference an
existing file path or ask Liatir to persist returned content.

```ts
return {
  report: {
    content: "sample,score\nA,0.92\n",
    fileName: "report.csv",
  },
};
```

Liatir registers saved file outputs under workspace Results so they can be
opened later or connected to downstream pipeline steps.

## WASM manifest

WASM tools keep their schema in `.lia-manifest.json`:

```json
{
  "name": "wasm-length",
  "version": "1.0.0",
  "description": "Count characters in text.",
  "runtime": "wasm",
  "inputSchema": {
    "text": { "type": "string", "label": "Text", "required": true }
  },
  "outputSchema": {
    "length": { "type": "number", "label": "Length", "format": "integer" }
  }
}
```

The WASM binary reads JSON input from stdin and writes JSON output to stdout.
